# 场记台 · 电影剧本连续性检查工具

使用 React、Vite、TypeScript 和 MUI 从零实现的电影剧本连续性工作台。项目围绕场景、角色、道具、服装、时间线与修订颜色建立真实数据关系，并在场景变化后自动给出可审阅的连续性警告。

## 功能

- 大纲视图、场景详情、资料库与响应式工作区。
- 维护场景、角色、道具、服装、故事时间、拍摄时段、修订颜色和锁定状态。
- 自动检查角色无铺垫出现、道具未提前建立、服装与时间冲突、时间线倒退。
- 审阅人逐条接受或忽略警告，作者可回复并保留修改理由。
- 全文搜索场景名、摘要、地点、故事时间和修改理由。
- 保存不可变版本快照，将历史版本与当前工作稿逐字段比较或恢复。
- 双标签页协作：两名场记分别拥有“场景/道具/服装”与“警告/回复”所有权，断网恢复后做共同原稿三方合并，同字段冲突保留两版人工选定，合并中断/重开可继续，合并前完整稿自动入快照且可撤销回退。
- 撤销重做、自动本地保存和常用键盘操作。
- Service Worker 运行时缓存，已访问的生产页面可离线打开。

## 技术栈

- React 18
- Vite 6
- TypeScript
- MUI 6 + Emotion

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器默认使用本地端口 `5174`，该端口不代表容器映射。生产容器仅监听 `80`。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1017 .
docker run --rm -p 10017:80 sologsb-1017
```

Dockerfile 使用多阶段构建，最终由 nginx 在容器 `80` 端口提供静态文件。宿主端口由根编排文件维护，源码中没有硬编码宿主端口。

## 双标签页协作与断网合并

顶部“协作”入口（或状态栏下方横幅）开始：

1. 两个浏览器标签页分别打开本工具，一个选择**场记甲（场景/道具/服装）**，另一个选择**场记乙（警告/回复）**。第一个加入的标签页冻结共同原稿（剧本 + 审阅决定 + 版本）。
2. 协作期间按身份加锁：甲稿只能改剧本内容，乙稿只能改警告状态与回复，互不可越权；两个标签页各自写入独立的草稿槽，不会互相覆盖。
3. 网络恢复后点“开始合并”。合并以共同原稿为基准做三方对比：
   - 场景、角色、道具、服装中只有一方改动的内容**自动合入**；同一字段两边都改过且不同，**保留两版**在合并面板中逐项选定；一方删除、另一方修改同一条目也交人决定。
   - 警告的接受/忽略状态与回复按确定性警告 id **只跟随各自版本里仍存在的同一警告**，绝不由场号/场名套用到合并稿的新场景；找不到归属的决定进入“脱离的审阅决定”清单归档，不丢弃。
   - 两边对同一警告的状态直接打架（一方接受、一方忽略）同样保留两版让人选定；回复按回复 id 取并集。
4. 合并开始即保存名为“**合并前完整稿**”的版本快照（含审阅状态与回复）。合并中断或直接关闭页面，重开后横幅会提示顶替对应身份继续，**待选定内容不丢**。
5. 完成合并后两页自动采用同一合并稿；Ctrl/⌘+Z 或在“版本差异”中恢复“合并前完整稿”都能**回到合并前**。

合并引擎为纯函数，`node scripts/run-merge-tests.mjs` 可直接运行其规则断言。

## 数据说明

剧本、审查决定、回复、版本快照、协作基线、各标签页工作稿与未决合并会话均保存在浏览器 `localStorage`（标签页身份标识用 `sessionStorage`）。应用不调用网络接口，清空站点数据会同时清空本地剧本与协作状态。
